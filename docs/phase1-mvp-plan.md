# Phase 1：最小可用测试方案（MVP 检修版）

## 1. 设计目标

* **硬件依赖极简**：不需要定制测试底板（治具），仅需 **1 根 USB-C 数据线** + **1 个测试用 2.4G/5G 双频 Wi-Fi 热点**。
* **针对售后高频故障**：覆盖用户使用后最容易损坏、且无需治具就能测准的 90% 核心硬件。
* **高效防呆**：自动项全自动跑批，人工交互项（按键/屏幕/光敏）防漏检、防卡死。
* **直观结论**：测试结束直接在屏幕显示 **PASS / REPAIR** 及逐项明细，便于维修员一眼定位坏件。

## 2. 第一阶段测试范围（做什么 vs 先不做）

### 2.1 第一阶段必做项（共 6 类 11 项）

| 序号 | 模块 | 硬件 / 引脚 | 测试方法与判定标准 | 覆盖的典型售后故障 |
| :---: | :--- | :--- | :--- | :--- |
| 1 | **电源开关与 Bootloader** | 侧边拨动开关 + USB-C (`PA24`/`PA25`) | 拨动开关上电；双击复位进 UF2 拖入测试固件即完成物理开关与 USB 烧录通路验证 | 拨动开关断脚、USB-C 虚焊/无法烧录 |
| 2 | **USB 串口通信 & 用户灯** | USB CDC + `LED_BUILTIN` (`PA15`) | 枚举串口并持续输出日志；测试期间蓝灯按节拍闪烁（PASS 常亮/慢闪，FAIL 快闪） | 主控供电/USB 数据线断线、LED 损坏 |
| 3 | **LCD 显示与背光** | 2.4" `ILI9341` + `LED_LCD` (`PC05`) | 全屏依次显示 红/绿/蓝/白/黑（每色约 0.5–0.8s，或按键步进），同时测试背光暗→亮；人工确认无花屏/坏点/背光失效后按键确认 | 摔碎、排线接触不良、背光升压电路损坏 |
| 4 | **顶部 3 个功能按键** | `WIO_KEY_A` (`PC26`), `B` (`PC27`), `C` (`PC28`) | **两段式检测**：① 上电先检查无按键常按/粘连（Stuck）；② UI 绘制 3 个方块，逐个按下对应方块变绿 | 按键进灰失灵、微动弹片塌陷/连键 |
| 5 | **5 向摇杆开关** | `WIO_5S_UP` (`PD20`), `DOWN` (`PD08`), `LEFT` (`PD12`), `RIGHT` (`PD09`), `PRESS` (`PD10`) | **两段式检测**：① 上电检查无方向粘连；② UI 绘制十字方向盘，5 个方向必须全部独立触发变绿才过 | 摇杆单方向失灵、歪斜卡死（**返修最高发**） |
| 6 | **4 MB QSPI Flash** | 板载 QSPI Flash (SFUD) | 对预留测试扇区执行 擦除 → 写入伪随机序列 → 回读比对；全程自动 | Flash 虚焊或损坏 |
| 7 | **3 轴加速度计** | ST `LIS3DHTR` (内部 I2C) | 读取 `WHO_AM_I` ID（`0x33`）；静态检测合加速度处于 `0.85g ~ 1.15g` 之间（可选提示轻微晃动验证数值变化） | 跌落导致芯片脱落/I2C 无响应/数据漂移 |
| 8 | **蜂鸣器 + 麦克风自闭环** | `WIO_BUZZER` (`PD11`) + `WIO_MIC` (`PC30`) | 先采样 200ms 计算环境底噪峰值/RMS，随后蜂鸣器以 `4000 Hz` 鸣响 300ms 同时麦克风采样；发声期能量显著高于底噪阈值即双方通过 | 蜂鸣器进水/断线不响、麦克风堵死/损坏 |
| 9 | **光敏传感器** | `WIO_LIGHT` (`PD01`) | 读取初始光照 ADC 值，提示操作员用手指短暂遮挡背面透明窗（或持续读 2s 检测下降幅度超过阈值），确认响应灵敏 | 光敏管损坏或开路/短路 |
| 10 | **无线芯片握手与版本** | `RTL8720DN` (`rpcWiFi`) | 检查 eRPC 通信握手成功，读取无线固件版本号及有效 MAC 地址（非全 0 / 全 F） | 用户刷坏 RTL8720 固件、无线模块死机/虚焊 |
| 11 | **2.4G & 5G Wi-Fi 扫描** | `RTL8720DN` 双频射频 | 扫描产线指定双频测试 AP 的 SSID（支持配置），校验 2.4G 和 5G 均能扫到且 RSSI ≥ `-70 dBm` | 天线焊点脱落、PA/RF 功放损坏 |

### 2.2 第一阶段暂不做项（待定 / 留待 Phase 2）

* **microSD 卡槽**（决策 D-004）：待定，暂不测。
* **BLE 蓝牙交互**（决策 D-005）：待定，批量干扰大，Phase 1 用 Wi-Fi 2.4G/5G 覆盖 `RTL8720DN` 验证。
* **940 nm 红外发射 (`WIO_IR`)**：需治具端红外接收头闭环，Phase 2 补充。
* **背面 40-Pin GPIO 排母 & 底部双 Grove 接口**：需制作专用回环（Loopback）测试板，Phase 2 补充。
* **PC 上位机管理软件 & 条码打印**：Phase 1 先以单机屏幕 + 串口助手文本观察为主。

## 3. 测验流程与界面设计（SOP）

单台设备目标测试时长 **25–40 秒**：

1. **Step 1：烧录启动（约 5s）**
   * 插上 USB-C 线，拨动电源开关开机；快速双击开关进入 `Arduino` UF2 磁盘，拖入 `wio_factory_test.uf2`（或通过命令行烧录）。
2. **Step 2：全自动后台检测（约 5–8s）**
   * 屏幕上电显示正在检测项进度，自动连续跑完：
     1. 按键/摇杆粘连检查（开机不可有任何键处于按下状态）
     2. QSPI Flash 读写校验
     3. `LIS3DHTR` 加速度计 ID 与重力校验
     4. 蜂鸣器 + 麦克风声学闭环（机器会短暂“嘀”一声）
     5. `RTL8720DN` 握手 + MAC/版本读取 + 2.4G/5G Wi-Fi 扫描（异步或同步进行）
3. **Step 3：人工快速交互检测（约 15s）**
   * **LCD 坏点/背光检测**：依次全屏刷纯色（红/绿/蓝/白/黑）及背光暗亮测试，操作员目检正常后按下任意指定确认键（如 Key A）通过，若屏幕异常则按 Key C 标为 FAIL（或超时/串口标记）。
     * *注：若按键坏了导致无法确认屏幕，可支持“串口指令跳过/标失败”或“5 秒倒计时自动跳下一项”。*
   * **按键与 5 向摇杆检测**：屏幕画出 3 个顶部按键框 + 十字摇杆框，操作员依次按一遍（共 8 个动作），全部变绿自动进入下一项；若某键按了没反应，等待超时（如 10s）或按下测试退出组合键，该项记录 FAIL 并标出具体失效的键名。
   * **光敏遮挡检测**：提示“请遮挡背面光敏窗”，检测到光敏 ADC 明显下跌即瞬间通过（若超时未变则标 FAIL）。
4. **Step 4：汇总结果界面（停留在屏幕）**
   * **屏幕可用时**：
     * 顶部大图块：**绿色 `PASS (全部通过)`** 或 **红色 `REPAIR (需检修)`**。
     * 中部列表：逐行显示 11 项状态（`[OK]` 绿字 / `[FAIL]` 红字 + 具体报错原因，如 `KEY_5S_UP: No response`、`WIFI_5G: RSSI -82 < -70`）。
     * 底部栏：设备 `RTL8720 MAC`、固件版本、总耗时。
   * **屏幕不可用时（黑屏/花屏兜底）**：
     * USB 串口会打印完整 ASCII 表格 + JSON 汇总报告，直接连接电脑串口终端即可查看“除屏幕外其他模块是否完好”。
     * 底部蓝灯：全部通过呈 **呼吸/慢闪**，存在故障呈 **急促双闪**。
