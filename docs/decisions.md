# 项目决策记录 (Decision Log)

本文档用于长期保留我们在项目讨论中达成的所有关键决策、背景原因及待定事项，避免后续开发偏离实际业务场景。

---

## D-001：核心业务场景为「售后/返修整机功能检修」
* **日期**：2026-11-15
* **状态**：已确定
* **内容**：本项目主要面对**用户使用过后的返修/回收设备**，核心诉求是判断设备“好还是坏”、是否需要修理，以及具体坏在哪个部位，同时也能兼顾整机出厂验收。
* **影响**：
  * 测试策略优先覆盖用户高频损坏模块（按键/摇杆磨损卡死、屏幕损坏、USB/开关故障、蜂鸣器/麦克风受潮、跌落导致传感器异常、无线固件被刷坏等）。
  * 结果展示必须**逐项明确标出失败模块与故障原因**，便于维修人员直接定位，而不只是笼统给一个总失败码。

## D-002：允许直接烧录测试固件，发给用户后由用户自行覆盖
* **日期**：2026-11-15
* **状态**：已确定
* **内容**：测试时允许直接通过 USB（如 UF2 Bootloader 拖拽或 PlatformIO 烧录）刷入本项目的测试固件；后续发出给用户使用时，用户会自行烧录覆盖原有固件。
* **影响**：
  * 无需在出厂展示固件（如 Jumper 游戏）中强行内嵌隐藏测试模式，降低固件耦合度与 Flash 占用。
  * 无需在测试结束后额外增加“恢复出厂演示固件”的二次刷机步骤（除非后续另有要求）。

## D-003：结果呈现以「机载屏幕直接显示」为主，串口日志兜底
* **日期**：2026-11-15
* **状态**：已确定
* **内容**：每台设备测完后，直接在 Wio Terminal 自身 LCD 屏幕上显示 **通过 (PASS)** 或 **需检修 (REPAIR)**，并展示具体哪几项通过、哪几项失败（前提是屏幕可用）。
* **补充约定**：针对“屏幕本身损坏（黑屏/花屏/白屏）”的故障机，通过 **USB 串口实时输出诊断报告** + **底部蓝色用户 LED (`LED_BUILTIN`) 闪烁状态** 作为兜底判断手段，确保屏幕坏掉时也能知道其他模块好坏。

## D-004：SD Card（microSD 卡槽）测试暂不纳入 Phase 1（待定）
* **日期**：2026-11-15
* **状态**：暂缓 / 待定
* **原因**：第一阶段先聚焦最小可用测试，插拔测试卡会增加单台操作时间且引入卡本身接触/兼容性变量。待后续评估返修中卡槽故障占比，再决定是否在 Phase 2 开启。

## D-005：BLE 蓝牙测试暂不纳入 Phase 1（待定）
* **日期**：2026-11-15
* **状态**：暂缓 / 待定
* **原因**：在批量测试场景下，BLE 交互配对/扫描易受多机并行干扰且测试节拍较长；Wio Terminal 的 Wi-Fi 与 BLE 共用 `RTL8720DN` 无线协处理器与射频通路，通常 **Wi-Fi（2.4G/5G）功能与信号正常即可基本确认无线模块无硬伤**。BLE 留待后续按需补充。

## D-006：第一阶段采用「零外设/零治具」最小可行测试集 (MVP)
* **日期**：2026-11-15
* **状态**：已确定
* **内容**：Phase 1 先只测仅靠一根 USB-C 线 + 现场 Wi-Fi AP 即可闭环验证的模块；需要定制硬件回环底板或外接传感器才能验证的接口（40-Pin GPIO、双 Grove、940 nm 红外发射）放到 Phase 2。

## D-007：测试工位免 PlatformIO 编译链（Linux / macOS 零依赖快速 UF2 烧录 + Runtime 直接展示）
* **日期**：2026-11-15
* **状态**：已确定
* **内容**：测试执行阶段不依赖 `pio` 编译环境。仓库提供预编译好的 `.uf2` 发布产物与版本清单（如 `dist/`），并配备仅依赖 Python 3 标准库的跨平台脚本（支持 Linux 与 macOS），自动识别接入的 Wio Terminal：
  * 串口模式下自动比对固件版本与构建指纹（一致则跳过烧录，不一致或无响应则通过 1200 bps 自动踢入 UF2 模式）；
  * UF2 模式下自动检测 `Arduino` 盘符并快速写入最新 `.uf2`（支持比对 `CURRENT.UF2` 载荷哈希记录状态，并触发设备重启立即运行测试）；
  * 烧录后由固件 runtime 在设备屏幕直接运行并展示 `PASS` / `REPAIR`，同时脚本侧同步透传/留档串口诊断结果。

## D-008：默认测试 Wi-Fi 为 `SEEED-Guest` 并直接执行连接验证
* **日期**：2026-11-15
* **状态**：已确定
* **内容**：将 `SEEED-Guest` / `SeeedGuest22` 写入 `include/test_config.h` 作为默认测试 Wi-Fi 配置（注意 `dist/manifest.json` 不写入密码字段）。
* **测试要求**：Wi-Fi 测项在完成双频扫描（确认 2.4G / 5G 均能扫到且信号达标）后，**直接调用 `WiFi.begin` 实际连接 `SEEED-Guest` 并获取 DHCP IP**，验证射频收发（TX/RX）与协议栈链路完整可用，测试结束后断开连接清理状态。

## D-009：Phase 1 MVP 改为「纯固件自动检测 + 多 Tab 实时交互看板」，默认不采集日志
* **日期**：2026-11-16
* **状态**：已确定（调整 D-003/D-007 交互与脚本默认行为）
* **内容**：
  * **取消所有强制人工确认与超时阻塞步骤**：不再在主流程中卡住等待 `LCD_BL`、`KEYS_5WAY`、`LIGHT` 按键确认或超时。上电即自动跑完 6 项全自动检查（`STUCK_KEY`、`QSPI_FLASH`、`IMU (LIS3DHTR)`、`BUZZER_MIC`、`RTL8720`、`WIFI_2G5G`）并立即给出 `PASS` / `REPAIR` 总结论（不依赖电脑或串口，接通供电即可独立展示）。
  * **多 Tab 交互式仪表盘（参考 `Love4yzp/wio-onboard-demo`）**：通过 5 向摇杆 `LEFT / RIGHT` 切换 Tab（摇杆不可用或翻页无响应即直接暴露滑杆故障）：
    * Tab 1 (`Auto Check`)：首 Tab 直接显示总判定与每项自动检测的 `[PASS]` / `[FAIL]` 明细（按 `A` 重测）；
    * Tab 2 (`Wi-Fi / Net`)：`RTL8720` 固件/MAC、2.4G/5G 信号与连网 IP 详情（按 `A` 重扫连网）；
    * Tab 3 (`IMU`)：`LIS3DHTR` 气泡水平仪 + 三轴 ±2g 实时交互；
    * Tab 4 (`Audio`)：`WIO_MIC` 实时波形 + VU 峰值柱（`A` 冻结，`B` 发 4kHz 测试音）；
    * Tab 5 (`Light & IO`)：`WIO_LIGHT` 实时光照柱 + `A/B/C` 音阶发声 + 8 键实时点亮指示；
    * Tab 6 (`LCD & Sys`)：内置 R/G/B/白/黑与灰阶目视条 + 系统版本/Build ID/内存/运行时间（按 `A` 触发全屏纯色轮播）。
  * **Tab 5 Key-Test Lock（D-009 补充）**：`NavPress` / `PRESS` 切换 Key-Lock。未锁定时 `LEFT / RIGHT` 照常切 Tab；锁定后 `LEFT / RIGHT` 留在 `Light & IO` 并点亮/锁存 L/R，便于完成 8/8 键检。再次 `PRESS` 解锁。锁定/解锁不重置已 seen 集合，只有离开或重新进入 Tab 5 才清零（进入方向会先计入 seen）；首次达到 8/8 时播放短提示音并把 `SEEN 8/8 PASS` 标绿。
  * **脚本侧默认只刷机、不采集**：`tools/auto_flash.py` 默认只负责识别设备、比对 `build_id` 并快速 UF2 烧录（刷完盘符卸载即完成），不再默认等待串口跑完或保存 `logs/*.json` / `.log`；串口仍保留文本/JSON 报告输出与可选 `--monitor` 调试模式。
